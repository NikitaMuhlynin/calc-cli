# Интерфейс плагинов, ABI v1

Публичный C-заголовок: `include/calc/plugin_api.h`.
Необязательный SDK для C++17: `include/calc/plugin_sdk.h`.
Общая проверка метаданных: `include/calc/plugin_validation.h`.

## Получение одной операции

DLL экспортирует ровно одну точку входа интерфейса с C linkage и `__cdecl`:

```cpp
CalcPluginStatus calc_plugin_get_api(
    uint32_t requested_version, uint32_t output_size, CalcPluginApi* output) noexcept;
```

Загрузчик ищет экспорт `CALC_PLUGIN_ENTRY_NAME` через `GetProcAddress`.
Клиент передаёт `CALC_PLUGIN_ABI_VERSION`, `sizeof(CalcPluginApi)` и адрес
своей структуры. В ответ DLL копирует описание ровно одной операции.
Имя файла DLL нигде в определении операции не участвует.

Версия 1 требует точного совпадения версии и размера структуры. Иначе
возвращается `CALC_PLUGIN_INCOMPATIBLE_ABI`; нулевой адрес структуры даёт
`CALC_PLUGIN_INVALID_ARGUMENT`. При ошибке структура клиента не изменяется.
Перед использованием клиент дополнительно вызывает `validation_error`:
нулевой результат означает корректное описание, иначе возвращается причина.

Хост и DLL должны иметь одну архитектуру; пресеты проекта используют Windows x64.
В ABI передаются `uint32_t`, `double`, массив символов и указатель на функцию.
У структуры задана упаковка 8. Объекты STL, C++-классы и владение памятью
через интерфейс не передаются.

## Метаданные и синтаксис

| Поле | Требование |
| --- | --- |
| `abi_version` | `CALC_PLUGIN_ABI_VERSION` |
| `struct_size` | `sizeof(CalcPluginApi)` |
| `name` | Непустое имя до 63 ASCII-символов и завершающий ноль |
| `kind` | `CALC_PLUGIN_FUNCTION` или `CALC_PLUGIN_INFIX` |
| `argument_count` | От 1 до 16; для бинарного оператора ровно 2 |
| `precedence` | Для функции 0; для оператора от 1 до 100 |
| `associativity` | Для функции `NONE`; для оператора `LEFT` или `RIGHT` |
| `invoke` | Ненулевой адрес функции вызова |

Именованная функция имеет идентификатор `[A-Za-z_][A-Za-z0-9_]*`;
регистр имеет значение. Планируемая форма вызова: `name(arg1, arg2, ...)`.
Бинарный оператор имеет один символ из `^%&|~!@?:`.
Встроенные операции, скобки, десятичная точка и разделитель аргументов
зарезервированы. Префиксные и постфиксные операторы ABI v1 не описывает.

Больший приоритет означает более сильное связывание: у встроенных `+ -`
приоритет 1, у `* /` — 2, у унарных знаков — 3.
Например, степень `^` описывается приоритетом 4 и `RIGHT`, чтобы
`2^3^2` разбиралось как `2^(3^2)`. При `LEFT` цепочка группируется слева.
Порядок аргументов при вызове совпадает с порядком в выражении.
Совпадения имён и символов между разными DLL проверяет будущий реестр.

## Вызов и время жизни

```cpp
CalcPluginStatus invoke(const double* arguments, uint32_t argument_count,
                        double* result, char* error_message,
                        uint32_t error_capacity) noexcept;
```

Все указатели принадлежат вызывающей стороне и действуют только на время
вызова. Плагин не сохраняет их и не освобождает память клиента.
Аргументы читаются слева направо, `argument_count` должен совпадать с описанием.
Нужны ненулевые `arguments` и `result`; буфер ошибки необязателен:
`nullptr` допустим только при нулевой ёмкости. Буферы не должны перекрываться.

При успехе записывается один конечный `double`, буфер ошибки становится пустым.
При ошибке `result` остаётся прежним. Если есть место, в буфер копируется
текст ошибки с завершающим нулём; длинный текст обрезается до `capacity - 1`
байт. При ёмкости 0 записи нет. Сообщения предназначены для человека;
логика хоста ориентируется на код статуса. Авторы сообщений используют UTF-8;
обрезание выполняется по байтам.

Копия метаданных принадлежит хосту, но указатель `invoke` действителен
только до выгрузки DLL. Хост обязан удерживать библиотеку, пока операция
может вызываться. ABI v1 предполагает последовательные вызовы.

## Ошибки и исключения

| Статус | Значение |
| --- | --- |
| `CALC_PLUGIN_OK` | Результат записан |
| `CALC_PLUGIN_INVALID_ARGUMENT` | Неверные параметры или метаданные |
| `CALC_PLUGIN_DOMAIN_ERROR` | Значение вне области определения |
| `CALC_PLUGIN_NUMERIC_ERROR` | Переполнение, ошибка диапазона или NaN/Infinity |
| `CALC_PLUGIN_INTERNAL_ERROR` | Другая ошибка реализации |
| `CALC_PLUGIN_INCOMPATIBLE_ABI` | Несовместимая версия или размер структуры |

Ни точка входа, ни `invoke` не должны выпускать C++-исключения через границу
DLL. Сам по себе `noexcept` не перехватывает исключения. SDK создаёт адаптер,
который проверяет аргументы и конечность чисел, ловит `std::domain_error`,
`std::invalid_argument`, ошибки диапазона, остальные `std::exception` и `...`.
Текст исключения копируется в буфер до уничтожения исключения внутри DLL.
При ручной реализации на C или C++ необходимо соблюдать тот же контракт.

## Минимальный C++-плагин

Рабочий пример — `plugins/stub.cpp`: файл `plugin_stub.dll` описывает
функцию `identity`. Реализация имеет сигнатуру
`double(const double* arguments, uint32_t count)` и может бросать исключения.
Описание создаётся через `calc::plugin::function<1, identity>("identity")`,
а точка входа делегирует работу `calc::plugin::publish`.
Для бинарной операции используется
`calc::plugin::infix<implementation>("^", 4, CALC_PLUGIN_ASSOC_RIGHT)`.
Счётчик аргументов в описании должен соответствовать реализации.

CMake-цель DLL связывается с `calc_plugin_api` и получает определение
`CALC_PLUGIN_BUILD`. Зависимости от библиотеки калькулятора у плагина нет.

В этом этапе определён и проверен контракт. Подключение этих операций
к разбору выражений и сканирование папки `plugins` выполняются следующим этапом.
