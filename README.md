# calc-cli

Консольный калькулятор на C++17 с расширением через DLL-плагины.

## Текущий этап

Реализована основа калькулятора: чтение строк, разбор выражений и вычисление.
Поддерживаются `+ - * /`, скобки, приоритеты, унарные минус и плюс,
пробелы и числа типа `double` с десятичной точкой и экспонентой (`.5`, `2.`, `1e-3`).
Умножение и деление выполняются раньше сложения и вычитания;
операции одного приоритета выполняются слева направо.

Определён [интерфейс DLL-плагинов ABI v1](docs/plugin-api.md): одна операция
на DLL, метаданные и вызов через C ABI с передачей ошибок кодом статуса.
`plugin_stub.dll` реализует пример `identity` через SDK. При запуске приложение
сканирует `plugins` рядом с `calc.exe` и регистрирует функции и бинарные операторы
из метаданных DLL. В комплект входят `funcsin.dll` (`sin` в градусах),
`funcdeg.dll` (степень `^`) и пример `plugin_stub.dll` (`identity`).

## Использование

Запустите `calc.exe` и вводите по одному выражению в строке:

```text
16 + 4 * (3 - 1)
24
2 * -(3 + 1)
-8
2^4 + sin(90)
17
```

Результаты выводятся в stdout, сообщения об ошибках — в stderr.
После ошибочной строки можно вводить следующую; пустые строки пропускаются.
Для завершения в консоли Windows нажмите Ctrl+Z, затем Enter.
Можно передать выражения через конвейер:

```powershell
'16 + 4 * (3 - 1)' | .\build\windows-msvc\bin\Debug\calc.exe
```

Код завершения — `0`, если все выражения вычислены успешно, и `1`, если
встретилась ошибка выражения, вычисления или чтения. Проверяются деление на ноль,
выход числа или результата за диапазон и некорректный синтаксис. Позиции в
сообщениях об ошибках отсчитываются с единицы. Числа используют обычную
точность `double`; например, результат `0.1+0.2` может содержать погрешность.

Путь к `plugins` определяется по расположению `calc.exe` и не зависит от
рабочей папки запуска. Отсутствие папки или пригодных DLL выдаёт предупреждение;
базовая арифметика продолжает работать. Повреждённые DLL, отсутствующий экспорт,
несовместимые метаданные и повторяющиеся имена пропускаются с диагностикой.
DLL проверяются в порядке имён файлов; при совпадении операции используется
первая пригодная DLL. Имя самой операции берётся только из её метаданных.
Предупреждения загрузки не меняют код завершения успешных вычислений.
Список DLL считывается при запуске; после добавления плагина нужно перезапустить
программу, пересборка калькулятора не требуется.

Оператор `^` имеет приоритет выше унарного минуса и группируется справа:
`2^3^2` равно `512`, `-2^2` равно `-4`, `(-2)^2` равно `4`.
Отрицательные и дробные показатели поддерживаются, например `2^-2 = 0.25`.
Для отрицательного основания показатель должен быть целым; ноль в отрицательной
степени и переполнение дают ошибку. `0^0` принято равным `1`, как у `std::pow`.
Синус принимает градусы, например `sin(30)` примерно равен `0.5`.

Ошибки функций включают имя операции, код и описание статуса, позицию вызова
в выражении. Если DLL не передала текст ошибки, хост формирует его по статусу.
Успех без записанного результата, NaN и Infinity отклоняются; текст ошибки
читается только в пределах выделенного буфера. После ошибки можно продолжать
вычисления следующей строкой.

Дескриптор DLL хранится в `shared_ptr` с освобождением через `FreeLibrary`
(RAII). Непригодные и повторяющиеся DLL освобождаются при отклонении.
Зарегистрированные операции и разобранные выражения совместно удерживают
библиотеку; она выгружается после освобождения последнего владельца.
Тесты проверяют фактическое наличие модулей в процессе, в том числе после
ошибки разбора, уничтожения реестра и нескольких циклов загрузки/выгрузки.

## Требования

- Windows x64.
- CMake 3.24 или новее, включая CTest.
- Visual Studio 2022 или Build Tools 2022 с компонентами разработки на C++
  и Windows SDK.
- Для первой конфигурации с тестами — Git и доступ к GitHub: CMake загружает
  GoogleTest автоматически. При `BUILD_TESTING=OFF` зависимость не требуется.

## Сборка и проверка

Команды выполняются из корня проекта в PowerShell. Пресеты используют MSVC;
запускать Developer PowerShell не требуется.

```powershell
cmake --preset windows-msvc
cmake --build --preset debug
ctest --preset debug
.\build\windows-msvc\bin\Debug\calc.exe
```

Для Release после конфигурации:

```powershell
cmake --build --preset release
ctest --preset release
```

CTest проверяет запуск, расположение результатов сборки, арифметику,
обработку ошибок, работу с несколькими строками ввода и контракт реальных DLL.
Публичный заголовок ABI также компилируется как C11.
Перед запуском тестов нужно собрать соответствующую конфигурацию.

Набор небольшой: 13 тестов GoogleTest в одном `calc_tests.exe` и 4 проверки
запуска/загрузки DLL через CTest. GTest 1.18.0 подключён через `FetchContent`
с фиксированным коммитом; отдельно устанавливать его не нужно.
Сборки зависимостей остаются внутри `build/`.

Запуск только юнит-тестов или только проверок приложения:

```powershell
ctest --preset debug -L unit
ctest --preset debug -L integration
```

Для запуска тестов по имени можно использовать фильтр GTest:

```powershell
.\build\windows-msvc\bin\Debug\calc_tests.exe --gtest_filter=Arithmetic.*
```

Проверка `calc.plugins_without_rebuild` сначала отклоняет неизвестную функцию,
затем добавляет новую DLL, перезапускает ту же копию EXE и проверяет результат.
Хеш EXE до и после установки плагина должен совпадать.

Результат сборки Debug:

```text
build/windows-msvc/bin/Debug/
  calc.exe
  plugins/
    funcsin.dll
    funcdeg.dll
    plugin_stub.dll
```

Для Release используется аналогичная папка `bin/Release`.

При необходимости сборку без тестов можно настроить отдельно:

```powershell
cmake -S . -B build/no-tests -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=OFF
cmake --build build/no-tests --config Release
```

## Структура

- `src/console.*` — чтение строк, вывод результатов и ошибок.
- `src/parser.*` — итеративный разбор в обратную польскую запись.
- `src/expression.h` — представление разобранного выражения.
- `src/evaluator.*` — вычисление разобранного выражения без обращения к консоли.
- `src/plugin_registry.*` — поиск, загрузка, проверка и реестр операций DLL.
- `src/main.cpp` — точка входа.
- `include/calc/` — C ABI, C++ SDK и проверка метаданных плагинов.
- `plugins/` — DLL-плагины `sin`, `^` и пример `identity`.
- `docs/plugin-api.md` — контракт плагинов и правила владения памятью.
- `tests/` — проверки через CTest.
- `CMakePresets.json` — воспроизводимые команды сборки и тестирования.

Создание своей функции описано пошагово в [инструкции плагинов](docs/plugin-api.md).

Стиль задаётся в `.clang-format` (clang-format 19): отступ в четыре пробела,
все открывающие скобки блоков — с новой строки (Allman), включая функции,
классы, пространства имён, условия, циклы, лямбды и блоки `try`/`catch`.
В последовательных объявлениях выравниваются имена переменных, а в
объявлениях с инициализацией и последовательных присваиваниях — знаки `=`.
Пустая строка или комментарий отделяют одну группу выравнивания от другой.
Эти правила применяются и к тестам, и к публичным заголовкам плагинов.

Форматирование всех отслеживаемых исходников из PowerShell:

```powershell
$sources = git ls-files -- '*.cpp' '*.h' '*.c'
clang-format -i -- $sources
clang-format --dry-run --Werror -- $sources
```
